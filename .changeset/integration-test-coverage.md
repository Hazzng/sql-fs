Make the integration suites actually run: 29 tests that skipped in every environment now execute, 5 that failed against a real database now pass, and the run no longer races itself.

**29 tests were permanently skipped.** Seven files gate on `REDIS_URL` — the five cross-replica/multi-tenant API suites plus `path-snapshot` and `redis-blob-cache` — and nothing in the repo said so, so a `DATABASE_URL`-only run reported 27 passed / 22 skipped on the API side and called it green. The guards are correct and stay; what changes is that `CONTRIBUTING.md` now states that `REDIS_URL` is not optional and names what is lost without it. Running them surfaced four assertions that had rotted while nothing executed them: three in the F8 heartbeat-gap suite still expected the retryable `LockLostError` where #175 M1 deliberately raises the non-retryable `LockLostAfterCommitError` (`ELOCKLOST_APPLIED`) once the guarded work has returned, and one expected `destroy` to `DEL` the Redis version key where F7 deliberately writes a `DESTROYED` tombstone. That last one now asserts the property the tombstone exists for — a warm session on a peer replica is torn down and the next request raises `ENOENT` instead of serving ghost state — rather than the shape of the key.

**Five `sql-fs` integration tests failed against any real database.** The epoch fence (#161) made `setSandboxContextWithLock` read the sandbox row to pin `app.sandbox_epoch`, so it now raises `ENOENT` — and never reaches `pg_advisory_xact_lock` — for an id that was never inserted. Four `advisory-lock` tests and one `blob-decoupled-tx` test locked ids they had not created; the serialization test then hung on a gate that was never signalled and burned the full 30 s timeout. They create the sandbox first, and the gate awaits now run through the file's `timed()` helper so the next such regression is a named timeout rather than a hang. The lock tests still assert serialization.

**The run raced itself.** `git-sqlfs` called `runMigrations` on the shared database and `rls`/`fencing` re-applied `0005`/`0007` by hand, all in `beforeAll`. `ALTER TABLE … ENABLE ROW LEVEL SECURITY` takes an AccessExclusiveLock on `inodes`/`dirents`/`sandboxes`, so those files deadlocked against each other and against every other file's `INSERT` — non-deterministically, in whichever file lost the cycle, which is why `rls`, `mvcomposite-overwrite` and `fencing` variously passed, skipped or errored depending on run order. They assert the schema is migrated (`requireMigratedSchema`) instead, which fails loudly and lock-free on an unmigrated database; migration 0007's own idempotency was already covered against an isolated scratch database by `migrations.integration.test.ts`. `pnpm test:integration` also runs files serially now: 22 files against one database exhausts `max_connections` at its common default.

Two HTTP concurrency assertions in `concurrency.pg.test.ts` encoded issue order as admission order. Both requests verify their JWT asynchronously before reaching the session lock, so either can win, and the tests flaked under load while claiming ("whichever runs first") to be order-independent. They now assert the order-independent invariants their names promise, which is strictly tighter than before: the PUT is *always* 204 and only the explicit `mkdir` may return 409; the DELETE is *always* 204 and the GET sees either the whole pre-delete file or nothing. Scratch-database teardown also stopped trying to `pg_terminate_backend` an autovacuum worker it has no privilege to kill.

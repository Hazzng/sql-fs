## Codebase Patterns
- Routes are created as factory functions: `export function fooRoutes(sessionManager): Hono<{Variables: AuthVariables}>` in `src/api/routes/foo.ts`, then mounted in `server.ts` with `app.route("/v1/sandboxes", fooRoutes(sessionManager))`
- Auth: all `/v1/*` routes use `authMiddleware` (already applied at app level) and ownership is checked with `checkOwnership(sessionManager, sandboxId, c.get("owner"))`
- just-bash tar requires GNU-style dash-prefixed flags: use `tar -xzf` NOT `tar xzf` (POSIX style without dash fails in just-bash with "You must specify one of -c, -r, -u, -x, or -t")
- InMemoryFs.writeFile accepts Uint8Array (binary data) — safe to write binary archives
- `mkdir -p` in just-bash must create `/tmp` before writing to `/tmp/...` via `fs.mkdir` API; InMemoryFs doesn't auto-create parent dirs for writeFile (the route must ensure parents exist)
- Tests use `InMemoryFs` + real just-bash `Bash` (no mocking needed for exec) — commands actually execute in the virtual FS
- Biome lint: use dot notation `body.archive` not bracket notation `body["archive"]` for object keys (enforced as error)
- MCP transport for Hono: use `WebStandardStreamableHTTPServerTransport`; mount with `app.all("/mcp", (c) => handleMcpRequest(c.req.raw))`; one McpServer+transport per MCP session
- MCP tools are registered on McpServer before `server.connect(transport)` — future tools go in `src/api/mcp/tools.ts`

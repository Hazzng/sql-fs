## Codebase Patterns
- Test mocking: Use `vi.mock('./dialects/postgres.js', () => ({ PostgresDialect: vi.fn().mockImplementation(...) }))` to avoid real DB connections in unit tests; mock `transaction` with `vi.fn().mockImplementation(async (fn) => fn({}))` and `loadAllPaths` with `vi.fn().mockResolvedValue([])` so `SqlFs.ready()` completes without DB access.
- Env var cleanup in tests: Do NOT use `delete process.env.VAR` (biome noDelete lint) or `process.env.VAR = undefined` (sets it to string "undefined", not truly unset). Use `process.env.VAR = ""` for "effectively unset" — the factory checks `if (!databaseUrl)` which treats empty string as falsy.
- The branch for Phase 2 HTTP API is `ralph/phase2-http-api` (was on `ralph/phase1-sqlfs-postgres` at session start).
- `StorageBackend` type and `InodeKind` are exported from `src/fs/sql-fs/index.ts`.
- `InMemoryFs` is exported from `just-bash` (no constructor args required for default use).
- Hono testing: Use `app.request('/path')` directly — no real HTTP server needed. Returns a `Response` object. Import `app` from `server.ts` which exports the Hono instance.
- Hono status codes: `c.json()` requires `ContentfulStatusCode` not plain `number` or `StatusCode`. Cast via `as ContentfulStatusCode` from `hono/utils/http-status`.
- Biome `biome-ignore` suppression: Only suppress rules that are actually enabled. Unused suppressions produce warnings. Verify by checking if the rule exists in biome.json before adding.
- Hono entry-point detection: Use `import.meta.url.endsWith(process.argv[1].replace(/^.*\//, ""))` to guard `serve()` call so it only runs when the file is the direct entry point (not in tests).
- Hono typed middleware: Use `createMiddleware<{ Variables: { key: type } }>` from `hono/factory` — NOT `MiddlewareHandler` without env param, which prevents `c.set()` calls (BlankEnv has no Variables). Export the Variables type for downstream apps to use in `new Hono<{ Variables: T }>()`.
- `res.json()` returns `unknown` — cast with `as { field: type }` in tests before accessing properties.
- Generic Hono middleware factories: use `createMiddleware<{ Variables: { key: z.infer<T> } }>` for typed variable injection; test apps need `new Hono<{ Variables: { key: z.infer<typeof schema> } }>()`.
- Zod for query params: use `z.coerce.number()` since query string values are always strings.
- `async-mutex` `Mutex.runExclusive(async () => { ... })` is the idiomatic pattern for serialized async critical sections in this project.
- Single-flight pattern: store `Promise<T>` (not `T`) in a pending `Map`; remove in `finally` so the slot is freed on completion or error.
- `SessionManager` in `src/api/session-manager.ts` is the canonical way to get a warm `Bash + IFileSystem` session per sandbox — route handlers use `withSession` not `getOrCreate` directly.
- Hono wildcard with slashes: use `/:param{.*}` (regex syntax) instead of `/*` — `c.req.param("*")` always returns `undefined` in sub-routers; use `c.req.param("param")` to get the full path including slashes.
- InMemoryFs error format: `stat()` throws with `code: undefined` but message starts with the POSIX code (e.g., "ENOENT: no such file..."). Use `err.message.match(/^([A-Z]+):/)` as fallback when `.code` is absent to extract error codes for HTTP mapping.
- InMemoryFs pre-populated paths: `getAllPaths()` returns built-in system paths like `/bin/*`, `/dev/*`, `/usr/bin/*`. Tests that use prefix-less tree assertions must use an isolated prefix (e.g., `/myapp`) rather than asserting exact root-level path lists.

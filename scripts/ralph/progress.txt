## Codebase Patterns
- Both US-001 (SqlDialect interface) and US-002 (shared types) live in the same file `src/fs/sql-fs/types.ts`. Implementing US-001 requires defining the shared types (InodeRow, DirentRow, PathCacheEntry etc.) as they are referenced by the interface. US-002 acceptance criteria are therefore largely satisfied as a side-effect.
- `SqlDialect` is generic: `SqlDialect<Tx = unknown>`. Each dialect specialises `Tx` with its own transaction handle type so that transaction callbacks are fully typed.
- All fields on exported interfaces use `readonly` per project conventions (immutable after construction).
- Biome auto-reformats multi-line function signatures to single-line where they fit within 120 chars — let it do so rather than fighting it.
- For `PostgresDialect`, `Tx = postgres.TransactionSql` (from the `postgres` npm package). `setSandboxContext` uses `SELECT set_config('app.sandbox_id', $1, true)` (SET LOCAL equivalent). `transaction(fn)` delegates to `sql.begin(fn)`.
- `sandboxes.root_inode` is nullable BIGINT (no FK to inodes) to break the circular FK with `inodes.sandbox_id → sandboxes`. Set it immediately after inode creation within the same transaction.
- Integration tests live in `src/fs/sql-fs/integration/` and are excluded from `pnpm test:unit`. Use `describe.skipIf(!process.env.DATABASE_URL)` wrapper.
- Stub (not-yet-implemented) dialect methods should use `_` prefix on parameters and `throw new Error("not implemented")`. TypeScript infers `never` return which is assignable to any type.
- `postgres.js` template literals do NOT accept `bigint` parameters — TypeScript will error. Always wrap bigint values with `String(id)` before interpolating into `tx\`...\`` tagged templates.
- When returning `tx\`...\`` from an `async (tx) => ...` callback, always `await` it (`return await tx\`...\``). Returning a `PendingQuery` directly causes TS1058 because PendingQuery has a `.then` member that confuses the async return type checker.
- Private class methods with `#` prefix work fine in this TypeScript config (ES2022 target). Use them for dialect-internal helpers to keep the public interface clean.
- For dynamic UPDATE queries in postgres.js (where only a subset of columns should be updated), use `tx(patchObj)` where `patchObj` is a `Record<string, ...>` with snake_case DB column names. This generates `"col" = $N, ...` syntax cleanly without `tx.unsafe()`. E.g., `await tx\`UPDATE inodes SET ${tx(patch)} WHERE id = ${String(id)}\``.
- BYTEA columns (content_sha256) are returned by postgres.js as `Buffer` objects. `Buffer extends Uint8Array` so they are directly assignable to `Uint8Array` in TypeScript — no conversion needed.
- Integration tests that depend on stored procedures/DDL not covered by the base migration can apply that DDL in `beforeAll` via `tx.unsafe(migrationSql)` where `migrationSql` is read from the migration file using `fileURLToPath(new URL("../migrations/postgres/000N_name.sql", import.meta.url))`. `CREATE OR REPLACE FUNCTION` is idempotent so repeated runs are safe.
- When mocking `SqlDialect` in unit tests, use `{ ...mocks } as unknown as SqlDialect<unknown>` to bypass TypeScript's structural check on the generic `transaction<T>` method. Save individual mock references (e.g., `const txMock = vi.fn(...)`) outside the cast object so they can be used in `expect(txMock).toHaveBeenCalledOnce()` assertions.
- `ReadFileOptions`, `WriteFileOptions`, `DirentEntry` are NOT exported from `just-bash`'s main entry point. When implementing `IFileSystem`, extract these types via `Parameters<IFileSystem["readFile"]>[1]` (etc.) instead of importing from internal just-bash paths.
- `readdirWithFileTypes` is optional in `IFileSystem` (`?:`) — stubs do not need to include it.
- `lru-cache` evicts only when adding an entry would EXCEED `maxSize` (not when it equals it). In tests, use `maxSize: N-1` (e.g., 25 for three 10-byte entries) to force eviction — `maxSize: 30` for three 10-byte entries is exactly the limit so no eviction occurs.
- `contentCache` is `LRUCache<bigint, Uint8Array>` with `sizeCalculation: (v) => v.byteLength`. Private `_contentCacheGet/Set/Has` test helpers on SqlFs allow unit tests to verify cache state without implementing readFile first.
